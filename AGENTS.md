# Project architecture rules

- Keep eBay notification public-key normalization and raw-body signature verification in the shared notification helper so endpoint behavior and regression tests use the same cryptographic path.
- Browsers never read provider credentials: `integrations` exposes only non-secret columns to signed-in users, settings come through `get_integration_settings` (secrets stripped), and token-bearing connection tables are service-role only — so one dealership can never see another's sign-ins.
- Workshop flow is bike-gated: Repairs is the admin/owner decision queue; every approved fault creates one idempotently linked workshop job (including zero-cost work), and Jobs becomes visible to admin/mechanics only after every inspection fault on that bike is decided.
- Marketplace images use ordered `bikes.listing_photos` only; intake/workshop `bikes.photos` are never sent to any marketplace, so a bike with no listing photos fails photo checks instead of falling back.
- eBay payloads keep Brand only in item specifics and never send product.brand, product.mpn, or an MPN item specific: eBay treats product.brand as an incomplete BrandMPN catalogue pair, while MPN is only recommended for category 177831; bikes.mpn stays internal-only.
- Channel mark-ups, manual CSV toggles and title prefix/suffix live in `app_settings` under key `listing_channels:<business_id>` (app_settings is keyed by `key` only), with identical pricing/affix logic in `src/lib/channelPricing.ts` and `_shared/channel-pricing.ts` so exports and live listings match. `applyTitleAffixes` shortens the title middle (never mid-word) so affixes always survive the length cap (eBay 80, Shopify 255, Squarespace 200).
- Deferred workshop jobs (`jobs.deferred`, owner/admin only via DB trigger, reason required) never block Ready/Listed but always block handover: create-delivery-order returns 409 unless an owner/admin gives an override reason, logged in bike_activity.

- Detailing jobs auto-close via a `bikes` status trigger once a bike moves past cleaning, so every stage-change path (UI, edge functions, admin override) stays consistent.
- Shopify CSV exports follow the dealer's uploaded header template (app_settings key `shopify_csv_template:<business_id>`, kept separate so saving channel settings never wipes it); standard/SEO/Google columns are always system-filled and only metafield columns are dealer-mapped.
- One listing title across channels: `finalEbayTitle` (`_shared/ebay-title.ts`, mirrored in `src/lib/ebayTitle.ts` — keep in step) is the single title builder for eBay, Shopify, Squarespace and CSV exports, using the dealer's `listing_templates.title_format` (platform `ebay` row) and the bike's `ebay_listings.title_override`; channels differ only by length cap and prefix/suffix.
- Manual (CSV) Shopify listing state lives on `bikes.shopify_manual_*` / `shopify_delist_required_at`; DB triggers (bikes, bike_components, ebay_listings.title_override) set the stale/delist flags so every edit path stays consistent — UI only ticks/clears.
- Imported parts reuse a shared `components` row only when brand/model/MPN, normalised description and attributes all match (unique index includes description), so one bike's spec never appears on another bike's listing.
- Invoices are mirrored live from QuickBooks via the `invoice-view` function (never stored copies); customers open them at `/i/<invoices.public_token>` with no account, and the public response carries only what's printed on the invoice, so a guessed or leaked ID exposes nothing else.
- Invoice numbers come from `next_invoice_number()` using per-dealership `invoice_counters` (prefix + next number, atomic update), falling back to the global INV- sequence; signed-in callers are forced to their own dealership so numbering can't leak across tenants.
- Dealer isolation is enforced in three layers: every `business_id` table has a RESTRICTIVE `tenant_scope` policy, `set_business_id_default`/`guard_business_id_change` triggers force and freeze the caller's dealership, and every service-role edge function that takes a caller-chosen row ID calls `assertTenantRow` (`_shared/tenant.ts`) — a new table or function without these can leak one dealer's data to another.
- Money rules live in pure, import-free modules (`src/lib/quoteMath.ts`, `_shared/channel-pricing.ts`, `_shared/handover.ts`) with Deno `*_test.ts` in `_shared`, so rules are tested exactly as the app runs them.
- Browser errors (`src/lib/errorReporter.ts`) and background sync failures (`_shared/system-error.ts`, called from the QuickBooks/Xero error loggers and eBay sync functions) go to `system_error_logs` (super admin reads at /admin/errors), so faults are visible without dealers reporting them.
- Long lists fetch with `fetchAllRows` (`src/lib/fetchAll.ts`) and show 25 per page on screen, so they never stop silently at the 1,000-row server cap.
- Multi-step money/stock actions run as single Postgres functions (`record_bike_sale`, `record_part_sale`, `fit_stock_part`, `remove_slot_part`, `strip_component`, `break_bike`, `change_bike_stage`; SECURITY INVOKER so RLS and tenant triggers still apply) so a dropped connection can't leave half-done records; accounting syncs stay client-triggered afterwards. The `guard_handover` trigger blocks collected/delivered with open deferred jobs on every signed-in path, and `validate_app_setting` rejects bad settings values.
- Scheduled edge functions (ebay-order-sync, sync-failure-alerts) only run for pg_cron calls carrying `x-cron-token` from the service-role-only `scheduler_token` table (`_shared/scheduled.ts`), or for a signed-in manager where supported, so outsiders can't trigger cross-dealer work. Typeform OAuth state is HMAC-signed, so only admin-started connections are accepted.
- Every redirect or emailed link destination (OAuth return links, password reset) goes through `allowedOrigin` (`_shared/ebay-oauth-origin.ts`), and every CSV export cell goes through `neutraliseFormula` (`src/lib/csvSafe.ts`), so no caller can point users at another site or plant spreadsheet formulas.
